A buy, sell and give-away platform where every college gets its own branded marketplace: seniors pass things on, juniors pay less, and nobody's phone number ends up in a WhatsApp group.

The problem

Every year, seniors dump useful things that juniors then buy new.

Textbooks, cycles, coolers, mattresses, lab coats, scientific calculators. What selling does happen is in noisy WhatsApp groups, where:

  1. There's no search.You scroll and hope someone posted it recently.
  2. Photos are scattered.Across hundreds of messages, with no idea what's still available.
  3. You share your number.With strangers, just to close a deal.

HandMeDown gives each campus one place to list items with photos, search them (including books by ISBN), chat in-app without exchanging numbers, and get a notification when the thing you want shows up. Only students with that college's email can post or chat there.

Features

What it does

  • Many colleges, one platform

    Each college lives at /c/<slug> with its own name, logo, accent colour, meeting spots and categories. Any student can set one up from the site, no code or config.

  • College email only

    Anyone can browse. Only students with a confirmed email on that college's domain can post, chat or set alerts there. Gmail, Outlook and other public providers are refused.

  • Chat without numbers

    One real-time thread per listing per buyer, with unread counts, a warning if you type a phone number, and block or report.

  • Search, including ISBN

    Postgres full-text search with filters and sorting. Books carry a checksum-validated ISBN, searchable as ISBN-10 or ISBN-13.

  • Wishlist alerts

    "Notify me when a cycle under ₹2,000 is listed", sent by web push, at most once per alert per listing, only within your college.

  • Contrast-checked branding

    Any accent colour a college picks becomes accessible light and dark shades that meet WCAG AA. Colours that fail are nudged in lightness, keeping their hue.

  • Listings that load on hostel Wi-Fi

    Up to 5 photos, compressed and resized on the phone before upload. Mark items reserved or sold, and a rubber stamp lands on the photo.

  • Reports and roles

    A reported listing is hidden immediately until that college's moderators review it. College admins manage branding, spots, categories and their team.

  • Colleges stay separate

    A college's chats, alerts and reports are never visible from another college. Postgres Row Level Security enforces it, not just app code.

every query inside RLS

Supabase

Free tier

  • Auth: confirmed email = membership
  • Postgres, private app schema: college_id on every tenant row, RLS by membership, triggers, rate limits, full-text search
  • Storage: photo paths start with the college
  • Realtime: private chat channels, authorized by the same functions

The request path

  1. The college layout resolves the college from /c/[slug] and applies its theme.
  2. Every user-facing query runs inside withRls(user, fn), which opens a transaction and sets request.jwt.claims and role = authenticated, the same mechanism Supabase's own API uses.
  3. Postgres then enforces the same college-scoped policies on server queries, Storage uploads and Realtime subscriptions. A forgotten check in app code still can't leak another college's data.

Per-college branding

Same platform, each college in its own colour.

A college picks one accent colour when it signs up. HandMeDown derives accessible shades from it, while the brown, neutrals, type and spacing stay the same, so every marketplace still looks like HandMeDown. Both colleges below are demo colleges.
